# 経路操作時のネクストホップ参照カウントの試験

内部メッセージで経路を登録・置換・削除し、ネクストホップグループごとの参照カウントとFIBの内容を確認する。

- IPv4/IPv6で同じ経路を繰り返し登録しても、参照カウントが一定に保たれること。
- 同じ宛先アドレスでプレフィックス長が異なる経路を登録し、置換・削除が対象の経路だけに反映されること。
- 削除通知のネクストホップが保存済み経路のものと異なる場合も、保存済み経路が参照するグループのカウントを減らすこと。
- 存在しない経路や削除済みの経路への削除通知で、他の経路の参照カウントが変わらないこと。
- 複数の経路が同じグループを使う場合、最後の経路を削除するまでグループを保持すること。
- 経路表の確保や経路登録に失敗した場合、登録用に増やした参照カウントを元に戻し、既存経路を維持すること。
- SRv6 local SIDの繰り返し登録・変更・削除で参照カウントを更新し、削除対象以外のSIDを保持すること。

内部メッセージの処理関数を直接呼び出すため、NIC、hugepages、root権限は不要である。

## 実行方法

sdplaneのビルド環境を用意し、リポジトリのルートディレクトリでビルドする。

```sh
sh autogen.sh
./configure --disable-pktgen
make
```

続いて、ASan/UBSanを有効にして試験を実行する。

```sh
make -C tests/route-nexthop-references clean
make -C tests/route-nexthop-references check
```

RIBや内部メッセージの割当が型の要求するアラインメントを満たさない構成では、UBSanのアラインメント検査を無効にして実行する。

```sh
make -C tests/route-nexthop-references clean
make -C tests/route-nexthop-references check EXTRA_CFLAGS=-fno-sanitize=alignment
```

コンパイルオプションや検証対象のソースツリーを変更する場合は、実行前に`clean`で試験のビルド成果物を削除する。
ソースツリーを変更した場合は、sdplaneもビルドし直す。
`ROOT`には、configureとビルドを済ませた別のソースツリーを指定できる。
省略すると、この試験ディレクトリから見たリポジトリのルートを使う。

## 試験の仕組み

GNUリンカーの`--wrap`で`rib_new()`と`rib_route_add()`の呼び出しを差し替え、指定した呼び出しでそれぞれNULLと`-1`を一度だけ返す。
失敗の注入が実行されたことを確かめた後、グループごとの参照カウントとFIBを検査する。

Makefileでは、RIBマネージャー、内部メッセージ、経路ツリー、FIB、RIB、ネクストホップ、FDB、MDBのソースをASan/UBSan付きで再コンパイルし、残りのオブジェクトはsdplaneの通常ビルドからリンクする。
メモリリーク検査を有効にし、sanitizerがエラーを検出すると試験を停止する。
