# Netlink受信バッファの試験

Linuxの実際のNetlinkソケットを使い、通知用受信バッファの起動前設定と稼働中の変更、要求値と実際の容量の表示を確認する。ダンプ用ソケットの容量は変更しないこと、不正値や設定失敗で既存の設定を変えないこと、照会失敗とカーネルの上限による制限を表示することも検査する。

sdplaneのビルド依存を用意し、リポジトリのルートでconfigureを実行してから試験する。

```sh
sh autogen.sh
./configure --disable-pktgen
make -C tests/netlink-receive-buffer check
```

試験は対象のソースをASan/UBSan付きでコンパイルし、使用しない関数はリンク時に除外する。`setsockopt()`と`getsockopt()`の失敗はリンカーの`--wrap`で注入する。設定や照会に失敗しても、起動時のソケット作成と購読を継続することを確認する。

受信容量の期待値には、比較用ソケットへ同じ要求値を設定した結果を使う。`net.core.rmem_max`によって容量が制限される環境にも対応する。

root権限、NIC、hugepagesは不要である。通知取りこぼしへの効果は、この試験とは別に実プロセスの起動試験で確認する。
